# Warframe Build Calculator

An **inverse** build calculator for Warframe: instead of picking mods and seeing what stats come out, you pick the **target stats** you want — *at least* a value, or as *close* as possible — and the solver works out a build that lands there.

**Live site:** https://anoncollab.github.io/build-calculator/

Static GitHub Pages site. Vanilla HTML/CSS/JS, no build step, no external assets. Solves run in a Web Worker (with a main-thread fallback) so big searches never freeze the page. Your inputs (category, item, targets, routes, shard wallet, Forma budgets, part picks, ability locks, progenitor) are saved in your browser's localStorage, and builds can be shared via a short base62 code in the URL hash — an append-only index registry keeps a code meaning the same build across data updates (the pre-v1.5.1 long links still load), and a build can also be downloaded and re-uploaded as a file. The board itself is part of the build state: a board's polarity/Forma plan travels with it through saves and share links, so a shared or reloaded build restores with its plan intact rather than at default polarities (boards saved before plans existed derive the optimal plan on load). Layout is responsive — single-column stacking, scrollable tab bar, and ≥44px touch targets on phone screens (≤760px breakpoint).

## Categories (all 12 solve)

- **Warframe** — all 126 frames, max-rank paper (arsenal) stats.
- **Primary / Secondary / Melee / Archgun / Archmelee** — per-type damage breakdown with elemental combining in mod slot order, crit chance/multiplier, status chance, fire rate, multishot, magazine, reload, punch through; multi-attack weapons (incl. Incarnon forms) have an attack selector; melee gets a stance slot, weapons get their Exilus slot.
- **Companion** — survivability/bond mods; Link mods scale off owner stats you supply; modular MOAs and Hounds assemble from parts.
- **Companion Weapon** — Beast claws (with Penjaga posture slot), Robotic weapons, Hound melee.
- **Necramech** — Voidrig and Bonewidow with their own mod pool, 12 slots, capacity 80.
- **Kitgun / Zaw** — pick the parts; the site assembles the base stats from the parts, then solves mods on the assembled weapon.
- **Amp** — pick prism/scaffold/brace; amps take no mods, so the solve picks Operator/Amp arcanes only, per the game's build rules.

## How solving works

- **Per-stat target modes:** *Don't care* (side effects land here), *Closest* (minimise distance either direction), *At least* (hard floor — unmet floors are reported honestly, with the best effort found and what might unlock more), and *Maximize* (a fill phase spends leftover slots, capacity, Forma and wallet pushing the stat as high as it goes, in the priority order you rank — see **Compensated packages** below for how the fill handles pieces whose downside would break one of your floors). While *Maximize* is chosen, the target's value box is hidden — Maximize has no value to hit, and a visible leftover number reads as a cap the solver would honour; the typed value is kept and reappears intact when you switch back to *At least* or *Closest*. When the closest solve and the cheapest solve differ, both are returned. On weapons, individual damage types (Viral, Magnetic, Heat, …) are targetable the same way, and the solver optimises the elemental mod order to match.
- **Movement targets (frames):** four more targets join the frame list — **Sprint Speed** (a multiplier over the frame's own extracted sprint base, which varies per frame — 0.9 to 1.5 across the roster), **Parkour Velocity** (a percentage over the unmodified value; the data carries one upgrade type under its three wordings — Parkour Velocity, Bullet Jump and Mobility — so they solve as one stat), and **Aim Glide Duration** and **Wall Latch Duration** as two separate targets expressed in seconds (bases 3s and 6s per the wiki's "Maneuvers" page; Loki and Loki Prime latch from a 60s base). The percentage movement mods feed both duration targets — except glide-only Tractor Beam — and the Aerodynamic aura's flat seconds (+6s / +12s) are in the pools too. Pools otherwise: the extracted movement mods, the Sprint Boost aura, and Amber Archon Shards for Parkour Velocity, with the same per-stat breakdown chains as every other target.
- **Routes the solver may use** (each toggleable): Mods (incl. partial ranks as a fine-tuning dial, Corrupted/Umbral/Archon/set mods, plus item-restricted mods and **ability augments** — an augment equips wherever its ability is, including on a frame that subsumed that ability; the Ability augments route toggle surfaces augments for locking, since mechanic pieces are never solver-picked for stats), Arcanes, Archon Shards, Aura/Stance, Exilus slot, Legacy Arcane Helmets (defaults **off** — they're rare legacy items), Tome mods on a support Grimoire (cross-gear), **Helminth subsume** (at most one; abilities you lock are never replaced; donor frames' own family is excluded; Invigorations are excluded as weekly/random), and Conditional buffs (procced/stacking effects count only when on). The Conditional route carries a **build intent** — *Window* (stack everything for one big moment; the default) or *Upkeep* (burst-class pieces — event-triggered effects with windows ≤ 6s, classified per piece from the extracted descriptions — are excluded from the pools and the fill, so nothing in the build can fall off; locks override), or *Hybrid* (Upkeep's discipline plus a solver-chosen burst allowance of 1–2 pieces, named in the result; locked burst pieces never consume the allowance). Paper values are never discounted: a burst piece in an upkeep build is out, not fudged to a fraction.
- **Channel upkeep:** frames with a channeled ability get a **Channel drain** target (energy per second, read *at or below*) alongside the ability targets. Drain scales with both Ability Efficiency and Duration — `base × clamp((200 − Eff) / Dur, 0.25, 1.75)` per the wiki's "Ability Efficiency" and "Channeled Abilities" pages, with uncapped Efficiency counting toward drain — and a **Prefer Efficiency / Prefer Duration** dropdown picks which stat pays among drain-equivalent builds. The tracked ability is the frame's highest-drain channeled one, named in the target row and the results; base drains are parsed from each ability's own wiki page (17 abilities across 16 frames ship; per-enemy/per-corpse/time-growing drains are audit-labelled rather than forced into the formula).
- **Focus schools:** one Tenno school can be picked as a route (the Helminth-choice shape); its stat-modelled nodes apply as fixed contributions — e.g. Unairu's **Stone Skin** (+200 armor) — with `Focus · <School> — <Node>` breakdown steps, and conditional nodes are classified and obey the build intent like any other conditional piece. Coverage is honest: **5 of the 76 current nodes are stat-modelled**; the other 58 are listed with their full text as prose and 13 Operator-only nodes ship as documentation. Naramon and Vazarin have no modelled nodes, and the results say so when they're picked.
- **Archon Shard wallet:** per-colour normal/Tauforged counts you actually own, plus Ascent Fusion (3 same-colour → 1 Tauforged) and Coalescent Fusion (two colours → a fused shard) when you allow them. Results list exactly what is consumed and created. The **Spare the shards** preference makes the solver spend Forma (within your budget) before shards when either could cover a stat target.
- **Forma budgets are real constraints:** a per-item Forma budget ("Any" = unconstrained), a separate **Umbra Forma** count (default 0, the only thing that can polarity-match Umbra mods), Orokin Catalyst capacity for weapons, over-rank to 40 for Lich-family weapons and Paracesis (+2 capacity ranks per Forma, max 5), and a slot-by-slot polarity plan in the result. Forma is counted from the polarity pool, the way the game works — innate polarities plus one freely-swappable polarity per Forma spent — on every board: Warframes, weapons, Companions and Necramechs alike (the one exception is the melee stance slot, whose polarity never swaps in game, so it stays fixed with its own Stance Forma). Drain is priced the game's way too: a mod in a slot whose polarity matches its own costs half drain (rounded up), a mod in a slot of a different polarity costs 25% more (rounded up), and a mod in an unpolarized slot costs its full drain — so a build the solver calls affordable is affordable in game, and the board editor prices hand-set polarities by the same rule. The aura slot follows the game's own capacity rule — a matching polarity doubles the aura's drain as bonus capacity, a slot with no polarity grants the listed drain, and a mismatched slot grants **80% of the drain, rounded down** — and its polarity is changeable like any other slot's: the solver can buy the match with a regular Forma, or an **Omni Forma** toggle in the Forma panel makes the slot universal (the Omni counts as one Forma in the build's total, the way the game counts it). On every board the **Re-Forma** button re-derives the cheapest plan for your edited mods, or you can set any slot's polarity by hand and watch the Forma count update live.
- **Starting Pool (v1.9.0):** the Forma panel carries a per-item **Starting Pool** — the polarities you have *already* invested in the selected item, seeded from its innate polarities (regular slots plus the Exilus slot) and editable entry by entry. The solver plans against the pool as polarities you already own: rearranging them is free, new Forma goes only onto unpolarized slots, and results split **Forma already in** from Forma still needed, spelling out pure rearrangements ("X polarity swapped for Y") where the plan makes them concrete. The aura and stance slots keep their own selectors and are never part of the pool (the aura slot must stay constant across an item's configs; a stance polarity cannot swap with other slots at all). An opt-in **last-resort conversions** toggle (off by default) lets the solver convert one pool polarity into another — only when every other slot is already polarized and the build is otherwise unreachable — at +1 Forma per conversion, counted against the same Forma budget. Pools persist per item and travel in share codes; codes from older versions load with every item seeded from its innate polarities.
- **Lich progenitor:** Kuva/Tenet/Coda weapons show a progenitor element + bonus % field (25–60%); the bonus is applied as an innate element, as in game.
- **Costs are shown:** every chosen mod lists the Endo + Credits to rank it to its solved rank (wiki Fusion-page formula: base × (2^rank − 1)), with a build total.
- **Set bonuses:** with the Cross-gear Mods route on, the solver plans specific set mods onto specific support gear to complete reachable sets and counts them immediately — the Results tab carries a Cross-gear Mods plan saying what goes where. Bonuses whose effect is a mechanic rather than a paper stat are reported, not stat-applied. The Umbral and Sacrificial sets work the other way: their bonus enhances the set mods themselves, and that enhancement is fully modelled with per-mod values (Umbral Vitality and Umbral Fiber +30% with a second piece equipped and +80% with the third, Umbral Intensify +25% / +75%, both Sacrificial mods +25% as a pair). Enhancement scales each mod's own values, counts only pieces equipped on the same item, and never changes drain.
- **Cross-gear Arcanes (v1.10.0):** a separate toggle next to Cross-gear Mods, **off by default**. When on, Warframe and Necramech solves may *credit* ability-stat buffs (Strength / Duration / Range / Efficiency) from arcanes equipped on your **other gear** — an ability stat exists only on the Warframe, so an arcane granting one is buffing the frame from wherever it sits. Credited arcanes are reported as a plan (the arcane and the gear it must be equipped on) in their own results group and panel, join the build guide's wind-up / upkeep like any other conditional piece, and cost no arcane slot, capacity or Forma — they never occupy the solved item's arcane slots. They obey the same discipline as the item's own pieces: the Conditional route must be on for conditional arcanes, the build intent applies (Upkeep excludes burst-class credits, Hybrid counts them against the allowance), and the arcane ban list applies to them too. Only ability stats are credited — generic stats (Health / Armor / Energy / Shields) from other gear's arcanes are not, since for Operator arcanes those belong to the Operator. Coverage today is exactly one arcane: **Pax Bolt** (Kitgun, +30% Ability Strength / +30% Ability Efficiency on headshot kill) is the only non-Warframe arcane whose modelled effects grant ability stats.
- **Compensated packages (v1.11.0):** inside the Maximize fill, a piece whose negative effect would break an *At least* floor is no longer simply unusable. The fill first offers such mods at **every rank** (a Corrupted mod's downside scales per rank, so a mid rank can fit exactly under a floor where the max rank cannot), and when even that is not enough it may pair the move with **enabler** pieces — an aura, an Exilus or normal mod, or the item's own arcanes — and take the package only if the combined result holds **every** floor while still improving the Maximize stats. A package carries at most 2 enablers, the cheapest working package wins, packages are considered only for moves that are actually blocked (the fill never stockpiles surplus it doesn't need), and every package is labelled in the results with what was paired with what and which floor the pairing holds. Enablers live on the item itself — cross-gear mods and cross-gear arcane credits are never used as enablers — and they obey the same discipline as everything else (routes, locks and bans, the Conditional route, and the build intent: burst-class enablers are forbidden under Upkeep and count against the allowance under Hybrid). A related honesty note: when a floor in the finished build holds only because conditional pieces are active, the results say so and name the pieces. The **Use shards as enablers** toggle (Routes panel, **off by default**, independent of Spare the shards) extends the enabler list to Archon Shards: shards recruited purely as compensation, where all shards spent on one deficit count together as a *single* enabler (so a package may carry a shard bundle plus two other enablers), are costed after other enablers, and are spelled out in the results — which shards, and what they unlocked.
- **Aura selection (v1.12.0):** a Warframe solve never leaves the aura slot blank through neglect. The aura is chosen in this order: one the solver picked for the targets (or as a compensated-package enabler) stays; a fill move that is blocked only by capacity may be paired with a single aura whose capacity bonus makes it fit; after the solve, an aura that keeps the finished build valid while spending less Forma (or makes an otherwise-invalid finish fit) is slotted; failing all that, the slot takes a **fallback** from a reviewed per-polarity preference list that ships as data — broadly useful squad auras, ordered so a fallback never quietly distorts the solved stats — and finally any useful aura matching the slot's current polarity (the frame's innate polarity, or universal under the Omni toggle; an *Any*-polarity aura matches every slot and scores the doubled bonus everywhere). The fallback list is safety-filtered against the extracted aura data: an aura carrying a negative effect on you or the squad — including unmodelled self-harm like Combat Discipline's health loss on kill or Power Donation's Ability Strength cut — is never slotted automatically and never appears on the list. The results say **why** the aura was chosen (targets/enabler, capacity — with the Forma saved, or general squad fallback). The Aura route toggle and your bans govern throughout: turn the route off or ban every candidate and the slot stays blank, because that's your choice, not the solver's oversight.
- **Results are a build board, not just a table:** slots in real order with polarity, effective drain and Forma badges (Overframe-style), every stat expandable into its per-source influence chain, and the board is editable — reorder, re-rank, remove or swap any mod and the stats re-evaluate live with deltas against the solved build, so you can test your own ideas against the solver's. Builds that use conditional effects show a **Peak** (everything up) beside a **sustained floor** (the same build re-evaluated with burst effects down), and a **"How to get the most out of this build"** section turns the board into a play guide: a wind-up sequence for window builds (stack-builders first, tightest window last), upkeep cards for upkeep builds (what keeps each effect up, what drops it).
- **Direct the solver:** any mod or arcane can be *locked in* (must appear — the solver picks its slot; works for stat-less mods like Primed Sure Footed) or *banned* outright, and the Helminth route lets you force the exact subsume ability and which ability it replaces (non-modelled subsumes are carried as labelled build instructions, never fake stats).
- **Golden case, verified on the shipped data:** Follie with Ability Duration "at least 300" solves to **305% with zero Warframe mods** (Arcane Concentration + Arcane Ice Storm + Ris Invocation + 3× Tauforged Crimson shards).

Tabs: Item / Targets / Routes & Resources / Results / Acquisition. The Acquisition tab lists every build piece (including modular parts) with drop-source strings where the extracted data covers them, and a wiki link for every piece regardless.

## Known limitations (honest list)

- **80 arcanes are documented but not modelled** — their descriptions carry effects with no constant a paper-stat solver can use (enemy-scaled, conversion-without-a-constant, heals, pure mechanics). Each is listed with its reason in the project's arcane report; arcanes whose text states a usable value are modelled (86 of 166 carry at least one modelled effect: pattern-parsed, partial, or curated).
- **Primed Streamline is not in the pools** — the extracted game data still lists it, but it is retrieved content: released unintentionally for a short time in the Chinese build only, then removed by the developers, and unavailable on both builds (per the official wiki). The pipeline excludes it by name, so it appears in no pool, picker or acquisition list. A saved build or share code that names it still loads: a board entry is ignored with a warning, and a lock is dropped with a note in the results.
- **Arcane slots only hold arcanes equippable on the item** — a Warframe's arcane slots take Warframe arcanes. Arcanes belonging to other gear are never solver-picked for a frame's slots, even when their effects touch frame stats (a Kitgun arcane granting Ability Strength and Efficiency, say, or Operator and Melee arcanes granting Health and Armor); a saved build that locks one has the lock dropped with a note in the results instead of failing the solve. Before v1.9.2 the solver's arcane pool ignored gear type and could field such arcanes on a frame. (The Cross-gear Arcanes toggle above is the deliberate exception in *accounting*, not in slots: it credits such an arcane's ability-stat buff as a plan for its own gear — the arcane still never appears in the item's slots.)
- **Acquisition sources are partial** — the wiki's acquisition store keys drop records by whole item, not by individual mod, and contains no internal item names to join on (verified), so source strings cover a subset of pieces; every piece still gets its wiki link.
- **Mechanic set bonuses are reported, not stat-applied** — e.g. Augur's energy-to-shields conversion or Gladiator's per-combo-multiplier crit are not paper stats, so the solver counts and reports the pieces without folding them into the stat targets.
- **Most movement passives are not modelled, and three movement stats are not targets** — frame passives sit outside the stat model for every stat, with one exception: Loki's and Loki Prime's wall latch lasting 10× longer IS modelled, as their 60-second Wall Latch base (their Aim Glide base stays the standard 3 seconds). Zephyr's airborne movement changes carry no number in the extracted data, Chroma's extra jump is a jump-count mechanic, and Khora's speed boost exists only while Venari is active — none of those are modelled. Slide, gravity while aim gliding, and dodge/roll speed are not targets either — slide's feel is its friction half, not a single percentage.
- **Aim Glide and Wall Latch share one timer in-game** — the two duration targets are shown and solved separately (their mods and bases differ), but the seconds are not two independent pools that simply add during a single airborne stretch.
- **Flat seconds vs percentage increases on the duration targets** — the wiki states no stacking order, so the calculator applies the percentage to the base first and adds flat seconds after (the same order it uses for every pool stat). Treat that as a modelling assumption, not a sourced rule.
- Tome **Canticles** whose effect targets enemies are excluded from player-stat solving (their data doesn't mark the target); stacking Invocations are included.
- Paper stats only — no real-DPS simulation, no enemy/armor scaling. Conditional effects are labelled and toggle-gated.
- **The Starting Pool is a multiset, not a slot map** — swap guidance is exact where the derived plan itself permutes polarities across slots, and otherwise stays at the level the pool supports (which polarities end up where), rather than inventing slot-exact swap instructions for an edited pool.

## Data & refreshing

The site runs on a **data snapshot** extracted from the Warframe wiki — no live API calls. The local project pipeline (not in this repo) pulls the wiki's Lua data stores (Warframes, Mods, Arcane, Ability, Modular, Weapons, Companions, and more), computes frame stats at Rank 30 (the stores' stat fields are base-rank values, so the pipeline applies the documented rank-up gains and a validator recomputes every shipped value), derives numeric mod effects from the stores' description text with validator-checked positional pairing, extracts shard/Tome/aura/helmet/Helminth/brace tables from wiki pages and stores, assembles the full arcane pool, and trims everything into the `data/*.json` files served here. The whole chain is re-runnable end-to-end as a refresh drill (pull → validate → transform → extract → build site data → test suites); after a game update, re-run it, re-publish, and cut a new release so each release tag pins a site + data snapshot together.
